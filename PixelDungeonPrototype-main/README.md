# Pixel Dungeon Prototype

Unity 2022.3 / Built-in 2D pixel prototype. Open `Assets/Scenes/PixelRoom.unity`, enter Play Mode, click the Game view, and use **WASD or the arrow keys**.

角色在 XY 平面移动，斜向速度归一化；脚底 CapsuleCollider2D 与墙壁和桌子、木箱碰撞。摄像机在 LateUpdate 平滑跟随，并根据实际视口尺寸限制在房间边界内。人物及场景物件按照脚底 Y 坐标排序。生成的素材使用 PPU 16、Point 过滤、无压缩、无 Mip Maps。Pixel Perfect Camera 使用 320 × 180 参考分辨率。

## Settings to edit

- Select `Player`: `PlayerMovement > Move Speed` defaults to 4 units/second. Rigidbody2D uses zero gravity, rotation lock, continuous collision detection, and interpolation.
- Select `Main Camera`: `CameraFollow > Smooth Time` defaults to 0.12 seconds. Set 0 for immediate following. Room Min/Max describe the outer room rectangle. Projection is Orthographic.
- Input uses Unity's legacy `Horizontal` and `Vertical` axes. Active Input Handling is Input Manager (Old). No separate Input System or Cinemachine package is required.
- `Visual > PlayerVisual` alternates two pixel walking frames and flips horizontally. This prototype has no shooting, enemies, room switching, or jump system.
- Built-in pipeline uses `UnityEngine.U2D.PixelPerfectCamera`; URP uses its own Pixel Perfect component. The bootstrap detects the pipeline before configuring the component.

## Rebuild and validate

Use **Pixel Prototype → Create Demo Scene** to recreate the generated art and demo scene. This intentionally replaces `Assets/Scenes/PixelRoom.unity` and the generated art.

Use **Pixel Prototype → Run PlayMode Validation** to exercise actual FixedUpdate movement, diagonal speed, stopped input, wall/table collisions, camera tracking, room bounds, and the pixel camera. Results are saved to `Validation/playmode-results.json`. The temporary test object is created only while validation runs.

Headless bootstrap (quit is safe because bootstrap is synchronous):

```powershell
& 'D:\Unity\2022.3.62f3c1\Editor\Unity.exe' -batchmode -nographics -projectPath '<project-path>' -executeMethod PixelPrototype.Editor.PrototypeBootstrap.Build -quit -logFile '<bootstrap-log-path>'
```

Headless PlayMode validation (**do not use -quit**; the callback exits with code 0 on success, 1 on a failed check, or 2 on timeout):

```powershell
& 'D:\Unity\2022.3.62f3c1\Editor\Unity.exe' -batchmode -nographics -projectPath '<project-path>' -executeMethod PixelPrototype.Editor.PrototypeValidation.Run -logFile '<validation-log-path>'
```

If a compatible Pixel Perfect package is installed after scene creation, use **Pixel Prototype → Configure Pixel Perfect Camera**. For the provided Unity 2022.3 Built-in template, use its resolved 2D Pixel Perfect package rather than a Unity 6 package version.

## Source layout

- `Assets/Scripts/PlayerMovement.cs`: input and Rigidbody2D movement.
- `Assets/Scripts/CameraFollow.cs`: following and room viewport bounds.
- `Assets/Scripts/FeetYSort.cs`: feet-based SpriteRenderer order.
- `Assets/Scripts/PlayerVisual.cs`: walking sprites and facing.
- `Assets/Editor/PrototypeBootstrap.cs`: art generation and scene creation through Unity Editor APIs.
- `Assets/Editor/PrototypeValidation.cs` and `Assets/Scripts/PrototypeSelfTest.cs`: PlayMode checks.

All pixel art in this prototype is generated by local code in `PrototypeBootstrap`; no external assets are required.
