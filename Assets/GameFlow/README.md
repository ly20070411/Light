# 菜单与存档系统

从昨日完成的 `Emerge/Assets/GameFlow` 移植至当前 `Light-GitHub` Unity 项目。保留主菜单、设置暂停、手动存档、自动存档与备份恢复，并将存档内容接入当前角色和道具系统。

## 开始游戏

进入 Play 模式后首先显示主菜单，游戏暂停。

- **继续游戏**：读取手动和自动存档中时间最新且校验有效的一份。没有有效存档时按钮禁用。
- **开始游戏 / 新的游戏**：默认进入 `Assets/Scenes/PropsDemo.unity`。已有存档时会先要求确认；确认后重置背包、流程标记与场景道具，并生成新的自动存档。原来的手动存档保留，可从读取存档页面恢复。
- **读取存档**：分别选择手动存档或自动存档。
- **退出游戏**：正常退出时保存当前游戏进度。

游戏中点击右上角 **设置** 或按 **Esc** 打开暂停菜单，可继续游戏、保存游戏、保存并返回主菜单或保存并退出。正在对话时按 Esc 先取消当前对话。菜单和暂停期间禁止角色移动与道具拾取。

原有操作保持一致：WASD / 方向键移动、Shift 加速、E 交互、I 打开背包。向导对话中的 1 / 2 分别选择交给果实或不给。

## 保存内容与时机

存档记录当前场景、游戏时长、角色地图位置与启用状态，以及玩家背包、流程标记和已消耗道具实例。地图道具的实例 ID、定义 ID、位置、旋转、缩放与启用状态也会保存，因此拾取后的果实读取存档后不会重新出现。

对话游标和正在选择的分支不保存。读取存档后需要重新与角色交谈；交付仅在相关对白读完时提交，尚未读完的交付不会消耗果实。

自动保存默认每 **10 秒**执行一次，新游戏开始、窗口失去焦点、应用暂停和正常退出时也会保存。操作系统强制结束进程或断电时无法保证执行退出回调，可恢复的是最近一次成功保存的检查点。

## 存档位置与校验

正式存档目录为：

```text
Application.persistentDataPath/Saves/LightPrototype/
├── manual.json       手动存档
├── manual.json.bak   上一份有效手动存档
├── auto.json         自动存档
└── auto.json.bak     上一份有效自动存档
```

Unity 的 `Application.persistentDataPath` 随平台、公司名和产品名变化。单独的 `LightPrototype` 子目录用于避免与源 Emerge 项目的旧存档混用。本移植使用版本 2 的存档结构，源项目旧版战斗存档不兼容。

保存先写临时文件并刷新至磁盘，再进行原子替换；每份存档包含 SHA-256 校验。主文件损坏时尝试读取上一份有效备份，并在界面说明备份恢复。无效角色坐标、重复实例 ID 或损坏背包数据会被拒绝。手动保存失败时保留当前暂停中的游戏，排除存储问题后可重试。

## 编辑器安装与验证

- **Tools → 菜单与存档 → 安装或更新**：创建或更新菜单运行预制体，给场景角色设置存档身份并确认游戏场景已加入 Build Settings。菜单预制体位于 `Assets/Resources/GameFlow/GameFlow.prefab`，可调整默认游戏场景和自动保存间隔。
- **Tools → 菜单与存档 → 运行移植验证**：运行真实 Play 模式菜单、存档和果实交付流程，完成后自动退出 Play 模式。

验证专用存档写入项目内 `Temp/MenuSaveChecks_<随机 ID>/`，不会覆盖正式存档。报告位于 `Validation/menu-save-results.json`，包含逐项结果；验证超时也会留下已完成的检查及失败原因。

验证包括主菜单暂停、新游戏、设置暂停、果实拾取与交付后的存读恢复、手动和自动存档选择、新游戏保留手动存档、定时与系统事件自动保存、原子替换与备份恢复、非法数据拒绝、保存失败后继续游戏，以及跨场景单例控制器检查。
