# 菜单与存档系统

从昨日完成的 `Emerge/Assets/GameFlow` 移植至当前 `Light-GitHub` Unity 项目。保留主菜单、设置暂停、手动存档、自动存档与备份恢复，并将存档内容接入当前角色和道具系统。

## 开始游戏

进入 Play 模式后首先显示主菜单，游戏暂停。

- **继续游戏**：读取手动和自动存档中时间最新且校验有效的一份。没有有效存档时按钮禁用。
- **开始游戏 / 新的游戏**：先进入五亲加点界面，再加载游戏场景。已有存档时会先要求确认；分配并确认点数后重置背包、流程标记与场景道具，并生成新的自动存档。原来的手动存档保留，可从读取存档页面恢复。
- **读取存档**：分别选择手动存档或自动存档。
- **退出游戏**：正常退出时保存当前游戏进度。

游戏中点击右上角 **设置** 或按 **Esc** 打开暂停菜单，可继续游戏、保存游戏、重新分配加点、保存并返回主菜单或保存并退出。正在对话时按 Esc 先取消当前对话。菜单和暂停期间禁止角色移动与道具拾取。

原有操作保持一致：WASD / 方向键移动、Shift 加速、E 交互、I 打开背包。向导对话中的 1 / 2 分别选择交给果实或不给。

## 五亲加点

新游戏流程为：主菜单 → 五亲加点 → 确认加点 → 加载场景 → 正式游戏。五项初始为 0，共有 8 点可自由分配。点击“＋／－”增加或退回一点，也可以重置；允许某项为 0 或将全部 8 点投入同一项。分配完 8 点后才能点击“确认加点 · 开始冒险”。鼠标悬停在属性行上，会弹出解释及对应行为；移开后关闭，悬浮框限制在屏幕内。

| 属性 | 行为 | 悬浮解释 |
|---|---|---|
| 父母 | 强化 | 积累知识、继承经验，强化已有能力，并理解、分析当前处境。 |
| 子孙 | 创造 | 将想法变成实际成果，创造、制作或修复事物。 |
| 官鬼 | 应对 | 面对外界威胁与不利影响时，保护自身并作出应对。 |
| 妻财 | 支配 | 主动施加力量，改变目标的状态，取得控制权。 |
| 兄弟 | 同化 | 与他人及环境建立联系，通过观察、交流、探索和协作寻找出路。 |

确认后的数值写入主角 `CheckActorState.attributes`，随原有检定快照保存，后续按“基础点数 + 本次排盘加值”检定。加点期间游戏暂停，不写初始存档；返回主菜单或按 Esc 取消不会改动原有手动、自动存档。继续游戏、手动及自动读档直接恢复原属性，不重新加点；旧六属性存档在首次加载时进入五亲重新分配页，确认后保留剧情、背包、位置、侵染与既有检定结果；取消不改原存档。新版属性确认后不重复要求分配。

代码入口：`CharacterAttributeAllocation` 管理 8 点预算，`SixKinAttributes` 提供五项文案及战斗职责，`GameMenuUI` 与 `CharacterAttributeHover` 显示界面和悬浮框，`GameSessionController` 管理创建阶段及确认后的属性接入。

## 设置中重新加点

正式游戏中打开 **设置 → 重新分配加点**，可免费调整当前五亲的 8 点分配。页面带入当前点数，支持加减、重置、属性悬浮说明、固定倍率预览及零点类别警告。全部 8 点分配完毕后才能确认；返回设置或按 Esc 取消时，角色属性和原有存档保持不变。

点击 **确认修改 · 自动保存** 后，先将新加点与当前世界状态写入自动存档，再更新角色属性并返回暂停的设置页。保存失败时保留原加点和页面草稿，可排除问题后重试。背包、剧情、位置与侵染保持原状态；手动存档只有点击“保存游戏”才更新。

新的检定使用新基础点数，新的战斗使用新技能权重与固定倍率。已开始的检定保留其冻结的原基础点数；通过 `CheckActorState.TrySetAllocatedAttributes` 更新属性，不替换正在进行的检定会话。战斗期间禁用重新加点入口，控制器也拒绝直接调用，保证当前战斗的属性快照一致。

## 保存内容与时机

存档记录当前场景、游戏时长、角色地图位置与启用状态，以及玩家背包、流程标记和已消耗道具实例。地图道具的实例 ID、定义 ID、位置、旋转、缩放与启用状态也会保存，因此拾取后的果实读取存档后不会重新出现。

对话游标和正在选择的分支不保存。读取存档后需要重新与角色交谈；交付仅在相关对白读完时提交，尚未读完的交付不会消耗果实。

自动保存默认每 **10 秒**执行一次，新游戏开始、窗口失去焦点、应用暂停和正常退出时也会保存。操作系统强制结束进程或断电时无法保证执行退出回调，可恢复的是最近一次成功保存的检查点。

## 存档位置与校验

正式存档目录为：

```text
Application.persistentDataPath/Saves/LightPrototype/
├── manual.json       手动存档
├── manual.json.bak   上一份有效手动存档
├── auto.json         自动存档
└── auto.json.bak     上一份有效自动存档
```

Unity 的 `Application.persistentDataPath` 随平台、公司名和产品名变化。单独的 `LightPrototype` 子目录用于避免与源 Emerge 项目的旧存档混用。本移植使用版本 2 的存档结构，源项目旧版战斗存档不兼容。

保存先写临时文件并刷新至磁盘，再进行原子替换；每份存档包含 SHA-256 校验。主文件损坏时尝试读取上一份有效备份，并在界面说明备份恢复。无效角色坐标、重复实例 ID 或损坏背包数据会被拒绝。手动保存失败时保留当前暂停中的游戏，排除存储问题后可重试。

## 编辑器安装与验证

- **Tools → 菜单与存档 → 安装或更新**：创建或更新菜单运行预制体，给场景角色设置存档身份并确认游戏场景已加入 Build Settings。菜单预制体位于 `Assets/Resources/GameFlow/GameFlow.prefab`，可调整默认游戏场景和自动保存间隔。
- **Tools → 菜单与存档 → 运行移植验证**：运行真实 Play 模式菜单、存档和果实交付流程，完成后自动退出 Play 模式。

验证专用存档写入项目内 `Temp/MenuSaveChecks_<随机 ID>/`，不会覆盖正式存档。Console 实时记录逐项进度，最终报告位于 `Validation/menu-save-results.json`。报告通过文件替换写入，旧报告保留在 `Temp/MenuSaveReports`，避免文件读取占用造成原地覆盖失败；超时会记录失败原因。

验证包括主菜单暂停、新游戏、设置暂停、果实拾取与交付后的存读恢复、手动和自动存档选择、新游戏保留手动存档、定时与系统事件自动保存、原子替换与备份恢复、非法数据拒绝、保存失败后继续游戏，以及跨场景单例控制器检查。

2026-10-04 在 Unity 2022.3.12f1 中通过 128 项菜单、加点与存档检查，以及 41 项果实交付回归。加点检查包含预算边界、六种实际悬停事件、加减与重置、取消保护旧存档、确认后写入主角与初始存档、真实检定基础值以及读档恢复。`Validation/character-creation-preview.png`、`character-creation-tooltip-preview.png` 和 `character-creation-complete-preview.png` 为实际界面截图。

## 五亲流派规则

悬浮提示同时解释日常行为及“战斗中司防御 / 调息 / 攻伐 / 疗愈 / 控制”。每点提高对应检定基础值和高级技能抽取权重，并使所属技能基础效果增加 10%。界面实时显示固定倍率及零点类别警告；0 点类别无法抽取高级技能，常驻基础技能保留。定卦只影响每轮抽取。具体概率与效果规则见 `Assets/Battle/README.md`。

旧字段 `self` 和枚举序号 5 仅为存档兼容保留，不参与新角色加点。升级保留原会话的冻结数据，既有战斗继续按其保存版本结算；升级后的下一场战斗使用五亲属性快照。

2026-10-06 在 Unity 2022.3.12f1 中通过 145 项菜单、加点与存档检查，以及 41 项果实交付回归。覆盖五亲预算、真实悬停提示、零点警告、检定关联、旧存档重分配、取消不改动存档、确认后同步手动及自动存档，以及再次读档不重复要求加点。

设置重新加点功能追加验证后，在同一版本 Unity 中通过 176 项菜单、加点与存档检查、211 项战斗检查及 41 项果实交付回归。新增覆盖当前分配带入、取消不写存档、未完成草稿阻止保存、保存失败后重试、保留原世界与检定会话、新检定和战斗关联、自动读档恢复，以及真实战斗中的入口锁定。实际界面截图为 `Validation/settings-reallocation-entry-preview.png` 与 `Validation/settings-reallocation-preview.png`。
