# 六爻回合战斗 v0.3

Unity 2022.3；当前配置以 `Assets/Battle/Config` 内的资产为准。v0.1 数值表和 v0.3 分析报告保留为设计历史。

## 试玩与界面

1. `Tools > 战斗系统 > 打开测试场景` 选择单敌、双敌、三敌、防御或首领。按 Play，在主菜单点击“新游戏”，再点击场景里的“开始战斗”，或靠近终端按 E。
2. 战斗进入独立画面，主角在左，1～3 个敌人依次在右。点击敌人选择目标，金色描边和箭头表示选中；悬停可看本轮意图。立绘下方有红色 HP、蓝色 MP。
3. **每轮开始投掷铜币、逐爻定卦**。“快速定卦”可跳过等待。定卦后才选择本轮行动，不再逐个技能重新投币。中间显示卦名、可用高级技能及已知倍率。
4. 底部技能、背包、交涉、逃跑四页。技能按六亲排列，按钮只显示名称；本轮未解锁、次数耗尽或 MP 不足的按钮禁用。悬停显示耗蓝、效果、已知倍率、全场剩余次数和禁用原因；涉及状态的具体值显示在相邻弹窗。
5. 玩家可连续使用多个技能、物品，直到主动点击“结束回合”。每个存活敌人在敌方阶段各行动一次。立绘位移、闪色和图片提供占位行动反馈。
6. 交涉仍为剧情预留页。逃跑回到战前位置、地图道具、背包、检定和剧情状态；不提交胜败。定卦与敌方行动期间不能逃跑。该次挑战的种子在战前快照之前锁定，退出重进不能免费重抽。
7. Esc 可暂停、保存、读档。胜利页显示本次回合、最佳回合、累计胜利和已达成成就；返回地图后物品消耗保留。下一场恢复满 HP / MP。

五个场景已在 Build Settings 中，测试入口新游戏使用当前测试场景。原测试包仅发放一次：医疗包×2、凝神剂×1、驱秽符×1、散灵符×1。重打不会补充。**难度验收完全不使用物品**；物品提供额外容错。

### 定卦与解锁

每轮生成独立、可重现的 18 枚铜币结果，使用项目既有六爻排盘。对应六亲取本卦最高旺衰评分，缺失时为 0，评分限制 -2～2，倍率为 0.6 / 0.8 / 1 / 1.2 / 1.4。同轮所有该六亲高级技能共用已知倍率；基础技能固定 ×1。

从尚有全场次数的高级技能中开放 3 项，本轮内可重复使用至次数 / MP 耗尽。对应六亲出现次数越多，抽取权重越高；不排除负分或缺失六亲，避免无技能可用。只要相应池未耗尽，保证至少一项伤害技能、一项辅助技能。池不足时按实际剩余数量开放，全部耗尽仍可使用常驻基础技能。未使用的开放资格不带入下一轮。

同分代表爻取最下爻；动爻只增加重击易伤的命中次数。倍率不重新抽取敌方意图，敌方也不读玩家卦象。

### 状态与行动时点

- 直接伤害将卦势倍率、削弱、易伤 / 破绽、减伤相乘后四舍五入，先扣护盾再扣 HP。易伤在重击命中后施加：后续伤害 +20%，持续 2 次命中，代表爻为动爻时 3 次；刷新而不叠层。
- 玩家护盾累加至 40，减伤取较高值；下轮玩家开始清除。敌人护盾保护下一玩家阶段，随后敌方阶段开始清除。
- 调息 / 清心额外回蓝取较高值，不即时返还，下轮与自然回蓝同时结算后清除。生息下轮开始，支付 3 次；同类取更强回复量并刷新次数。
- 蚀念削弱玩家输出 20%，持续下一玩家阶段。灼伤每次结束玩家回合损失 5 HP，持续 2 次，忽略减伤和护盾；施加后先给完整玩家回合处理。破绽增加承受直接伤害 20%，从施加时至下一敌方阶段结束。重复施加刷新；清心和驱秽符立即移除三种异常。
- 封诀在评分≥0 时将一次耗 MP 技能替换为普攻，负分改为削弱 10%。缚灵评分 -2/-1、0、1、2 分别削弱 10%、20%、30%、眩晕。眩晕跳过一次行动、解除蓄势，并给予抵抗下一行动机会前再次眩晕的定力。抵抗时改为削弱 30%；首领始终抵抗眩晕。
- 首领蓄势当轮不攻击，下一轮预告基础伤害 42 的释放。可提前防御、护盾、封诀；释放后首领易伤 +25%，持续 3 次命中。
- 敌方本轮意图提前冻结，按权重、MP、HP、护盾、次数和冷却条件选择，采用独立随机序列。重击等特殊行动不连续使用；首领回复最多 2 次。队伍基础意图伤害预算 44，为后续存活敌人预留普攻额度；该预算不包含破绽增伤和灼伤。
- 下方“预告直接伤害”逐敌计算当前目标、控制、防御、护盾、破绽和四舍五入；它不包含结束玩家回合的灼伤。击杀、控制、加盾后数值随之更新。

物品不耗 MP、不定卦、不结束回合；数量受现有背包约束。只有胜败完成后清除该次挑战的锁定种子。

## 胜利记录与成就

`PropGameState.BattleVictories` 按遭遇 ID 和 `Rules.balanceVersion` 保存胜利数、本次回合、历史最少回合、最后结算 session ID。胜利结算幂等，读档不会重复累计，失败或逃跑不记录胜利。使用实际玩家回合编号，从第 1 轮起算。

当前已经实现并持久化：

- 首胜标记：`battle-achievement:first:<数值版本>:<遭遇ID>`。
- 速战标记：`battle-achievement:swift:<数值版本>:<遭遇ID>`；胜利回合不超过遭遇的 `swiftVictoryRounds`。
- 阈值：教学 3，双敌 / 三敌 / 防御 5，首领 8。速战是进阶目标，可使用物品；尚未区分物品使用成绩，也未做成就收藏页面。

更改平衡版本后使用独立成绩，避免不同配置的最佳回合混排。没有新增局外等级、装备或属性成长。

## 接入、替换美术和存档

- 新场景在 `PropDefinition` 的“战斗遭遇”字段指定配置，或调用 `BattleController.TryBegin`。战斗优先于该道具的检定 / 对话分支。`repeatable` 控制重打，`victoryFlag` 和入口的完成标记可供剧情检查。
- 背包沿用 `PropGameState`，地图物品可填写相同 inventoryKey。
- `Assets/Resources/Battle/BattlePresentation.asset` 替换背景、主角、图标、铜币、特效；敌人专属立绘替换敌人资产的 Battle Portrait。占位 PNG 在 `Assets/Battle/Art`。参考画布 1600×900，其他比例等比缩放。
- 战斗覆盖并冻结原地图；战前位置、背包、检定、剧情与地图对象另存回退快照。战中读档后仍可逃跑恢复，有会话时自动保存探索状态。
- 战斗会话 version 2 保存本轮铜币、已揭爻、开放技能、全场次数、状态、意图、敌方游标与数值版本。提交物品或胜利事务时拒绝半完成存档。外层 BattleSnapshot 与现有游戏存档版本保持兼容。
- 旧战斗会话 version 1 经 BattleLegacyEngine 继续逐技能定卦，不强行重抽或重复扣 MP；新战斗采用新流程。缺少战前快照的旧存档仍可继续，逃跑禁用。旧成绩使用 legacy 标签。
- 修改正在进行的战斗引用的技能数值或数值版本，可能使存档一致性验证失败；调参后从新游戏 / 新战斗开始验证。

## 验证与结构

`Tools > 战斗系统 > 运行战斗验证`：真实 PlayMode 核验规则、存档、界面与五个场景，输出 `Validation/battle-test-report.json` 及各页面截图。

`Tools > 战斗系统 > 运行无物品数值模拟`：运行 15,000 场配对种子战斗，输出 `Validation/battle-balance-report.json`。两项测试均使用隔离存档并恢复原场景。安装菜单只补缺失资产与占位引用，不覆盖现有配置、美术或场景。

结构：BattleEngine 负责结算；BattleController 负责时序、地图锁定与回退；BattleView 为 uGUI；BattlePresentation 管理素材；BattleProgressData 保存成绩；BattleLegacyEngine 兼容旧会话；BattleSelfTest、BattleBalanceTest 验证功能及数值。
