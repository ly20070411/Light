# 六亲点数战斗与原测试场景

新游戏现使用 v0.8 点数战斗：每轮定卦获得 `3 + 我最终点数` 行动点，每次行动或使用物品消耗 2 AP，可连续行动后主动结束回合。六项属性均默认 1 点，共分配 8 点。详细规则见 [点数战斗系统](../../Docs/点数战斗系统-v0.8.md)。

原来的 `BattleSingleDemo`、`BattleDualDemo`、`BattleTripleDemo`、`BattleDefenseDemo`、`BattleBossDemo` 已接入新系统，入口仍是 `Tools > 战斗系统 > 打开测试场景`。Play 后创建新游戏，点击“开始战斗”或靠近终端按 E。场景中按 P 可调整装备顺序、精神锚和唐晦改装；示例装备与两个精神锚仅发放一次，不自动装备。

新旧规则共用 `BattleView` uGUI：原背景、主角与敌人立绘、四页操作面板、选中高亮、相邻状态说明弹窗、铜币动画和行动特效。新版主角蓝条显示 AP，敌方蓝条显示护盾；五种行动按最新六亲归属排列，按钮仅显示行动名称。多于三个敌人时右侧队列可横向滚动。

点数敌人配置位于 `Assets/Resources/Battle/PointBattleRules.asset`，包含原测试敌人的 E01/E02/E03/B01 配置，采用独立生命与循环意图。已有旧版战斗快照仍按原规则运行。

如重新生成了原测试场景，运行 `Tools > 点数战斗 > 接入原五个战斗测试场景`。功能与场景交互验证：`Tools > 点数战斗 > 运行功能与存读档验证`。

## v0.6 历史规则与兼容配置

当前主库已接入《技能表.docx》的 30 条新技能与 3 个基础指令。完整费用、次数、持续回合、五亲定位与数值测试见 [新版技能表实现与数值](../../Docs/新版技能表实现与数值-v0.6.md)。

玩家为 100 HP、30 MP；后续每轮恢复 18 MP。每轮定卦解锁最多 3 个五亲技能，第 3 轮起另抽 1 个终结技能。五亲达到 3 点且抽中对应技能时，自动使用一次强化；同一技能本场后续使用恢复普通效果，MP 费用一致。普攻、守御和清心常驻，玩家继续通过“结束回合”交出行动权。

技能页保留五亲列，列内可滚动；“终结 / 被动”子页提供独立终结按钮和被动说明。金色边框表示当前可强化。悬停可查看耗蓝、剩余次数、状态与反震说明。吉凶技能施放时展示独立铜币结果；暴击初值为 20%、伤害 1.5 倍。

试玩仍使用 `Tools > 战斗系统 > 打开测试场景` 下的五个场景。验证入口：

新版成绩按 `v0.6-skill-table` 记录，保留胜利轮数、最佳轮数与速战成就。旧版 v0.5 进行中的存档使用独立旧配置继续结算，之后的新战斗恢复新版主库。

## 试玩与界面

1. `Tools > 战斗系统 > 打开测试场景` 选择单敌、双敌、三敌、防御或首领。按 Play，在主菜单点击“新游戏”，完成五亲 8 点分配，再点击场景里的“开始战斗”，或靠近终端按 E。
2. 战斗进入独立画面，主角在左，1～3 个敌人依次在右。点击敌人选择目标，金色描边和箭头表示选中；悬停可看本轮意图。立绘下方有红色 HP、蓝色 MP。
3. **每轮开始投掷铜币、逐爻定卦**。“快速定卦”可跳过等待。定卦后才选择本轮行动，不再逐个技能重新投币。中间显示卦名、可用高级技能及已知倍率。
4. 底部技能、背包、交涉、逃跑四页。技能按六亲排列，按钮只显示名称；本轮未解锁、次数耗尽或 MP 不足的按钮禁用。悬停显示耗蓝、效果、已知倍率、全场剩余次数和禁用原因；涉及状态的具体值显示在相邻弹窗。
5. 玩家可连续使用多个技能、物品，直到主动点击“结束回合”。每个存活敌人在敌方阶段各行动一次。立绘位移、闪色和图片提供占位行动反馈。
6. 交涉仍为剧情预留页。逃跑回到战前位置、地图道具、背包、检定和剧情状态；不提交胜败。定卦与敌方行动期间不能逃跑。该次挑战的种子在战前快照之前锁定，退出重进不能免费重抽。
7. Esc 可暂停、保存、读档。胜利页显示本次回合、最佳回合、累计胜利和已达成成就；返回地图后物品消耗保留。下一场恢复满 HP / MP。

五个场景已在 Build Settings 中，测试入口新游戏使用当前测试场景。原测试包仅发放一次：医疗包×2、凝神剂×1、驱秽符×1、散灵符×1。重打不会补充。难度验收分别测试无物品、初始测试包，以及额外一瓶凝神剂的双回蓝压力包。

### 首领潮棘与流派取舍

死海残响具有 60% 潮棘反震。每次受到实际 HP 伤害后，立即反震该伤害的 60%；按主角当时的减伤、破绽和护盾结算。敌方护盾吸收的伤害不触发反震，溢出伤害不计入，致命攻击与伤害物品也会触发。双方同时倒下判失败。普通敌人的反震比例为 0；旧 version 1 / 2 会话不获得这项新机制。

首领状态栏和悬浮意图显示反震比例及应对方式；攻击、伤害物品的悬浮提示显示当前预计反震 HP 损失。攻击前加减伤或护盾会即时更新预览。减伤和护盾可同时覆盖反震与后续敌方行动；治疗负责持续进攻所需的 HP，控制降低敌方阶段压力。官鬼点数仍提供原有伤害倍率，高输出需要配合防御或续航投资。

本次数值版本为 `v0.5-counterplay`，成绩与旧版本分开记录。数值调整前的进行中战斗存档不能用新配置直接继续，需要从战前存档或新战斗开始；不会改写旧存档文件。

### 定卦与解锁

每轮生成独立、可重现的 18 枚铜币结果，使用项目既有六爻排盘。定卦只参与高级技能抽取，不参与倍率、控制强弱或易伤持续次数。

新角色将 8 点分配给父母（防御）、子孙（调息）、官鬼（攻伐）、妻财（疗愈）、兄弟（控制）。所有技能的数值效果使用固定属性倍率 `1 + 0.10 × 对应点数`，包含常驻技能；0～8 点对应 ×1.0～×1.8。减伤、护盾、回复和回气仍遵循原上限。沉默、眩晕和净化使用固定技能规则；缚灵对抗控敌人的削弱为 `20% × 属性倍率`，上限 50%。

高级技能最多开放 3 个不同技能。先按六亲抽取，再从该亲有效技能中等概率抽取。六亲权重为 `点数 × (1 + 0.25 × 本轮同亲爻数)`；代码使用等价整数权重 `点数 × (4 + 爻数)`。每次抽取概率是该亲权重 / 当前有效六亲总权重。抽出技能后移出本轮候选池并重新计算，技能较多的六亲不会自动获得额外类别权重。不强制保证攻击或辅助选项。

0 点类别和全场次数耗尽的技能不会进入候选池。有效池不足 3 个时只提供实际数量，全部耗尽仍可使用常驻基础技能。本轮内可重复使用已解锁技能至次数 / MP 耗尽；未使用的开放资格不带入下一轮。

战斗开始冻结五亲点数，预览、结算和存档校验共用 `BattleBuildRules`。同一属性快照、种子和使用记录产生同一抽取结果，读档与逃跑重进不重抽。新战斗会话版本为 3；已有版本 1 / 2 的进行中战斗保留原规则，下一场启用新规则。旧倍率表仅供旧存档恢复使用。

控制台 `[战斗链]` 与 `Validation/RuntimeLogs/battle-logic.jsonl` 实时记录属性快照、卦盘爻数、抽取权重、抽签结果、固定倍率和结算；构建版本日志位于 `Application.persistentDataPath/RuntimeLogs`。

### 状态与行动时点

- 直接伤害将属性倍率、削弱、易伤 / 破绽、减伤相乘后四舍五入，先扣护盾再扣 HP。易伤在重击命中后施加：后续伤害 +20%，持续 2 次命中；刷新而不叠层。
- 玩家护盾累加至 40，减伤取较高值；下轮玩家开始清除。敌人护盾保护下一玩家阶段，随后敌方阶段开始清除。
- 调息 / 清心额外回蓝取较高值，不即时返还，下轮与自然回蓝同时结算后清除。生息下轮开始，支付 3 次；同类取更强回复量并刷新次数。
- 蚀念削弱玩家输出 20%，持续下一玩家阶段。灼伤每次结束玩家回合损失 5 HP，持续 2 次，忽略减伤和护盾；施加后先给完整玩家回合处理。破绽增加承受直接伤害 20%，从施加时至下一敌方阶段结束。重复施加刷新；清心和驱秽符立即移除三种异常。
- 封诀固定将一次耗 MP 技能替换为普攻。缚灵固定眩晕普通敌人一次行动、解除蓄势，并给予抵抗下一行动机会前再次眩晕的定力；首领或有定力时转为 `20% × 兄弟属性倍率` 的削弱，上限 50%。控制不读取卦势或动爻。
- 首领蓄势当轮不攻击，下一轮预告基础伤害 42 的释放。可提前防御、护盾、封诀；释放后首领易伤 +25%，持续 3 次命中。
- 敌方本轮意图提前冻结，按权重、MP、HP、护盾、次数和冷却条件选择，采用独立随机序列。重击等特殊行动不连续使用；首领回复最多 2 次。队伍基础意图伤害预算 44，为后续存活敌人预留普攻额度；该预算不包含破绽增伤和灼伤。
- 下方“预告直接伤害”逐敌计算当前目标、控制、防御、护盾、破绽和四舍五入；它不包含结束玩家回合的灼伤。击杀、控制、加盾后数值随之更新。

物品不耗 MP、不定卦、不结束回合；数量受现有背包约束。只有胜败完成后清除该次挑战的锁定种子。

## 胜利记录与成就

`PropGameState.BattleVictories` 按遭遇 ID 和 `Rules.balanceVersion` 保存胜利数、本次回合、历史最少回合、最后结算 session ID。胜利结算幂等，读档不会重复累计，失败或逃跑不记录胜利。使用实际玩家回合编号，从第 1 轮起算。

当前已经实现并持久化：

- 首胜标记：`battle-achievement:first:<数值版本>:<遭遇ID>`。
- 速战标记：`battle-achievement:swift:<数值版本>:<遭遇ID>`；胜利回合不超过遭遇的 `swiftVictoryRounds`。
- 阈值：教学 3，双敌 / 三敌 / 防御 5，首领 8。速战是进阶目标，可使用物品；尚未区分物品使用成绩，也未做成就收藏页面。

更改平衡版本后使用独立成绩，避免不同配置的最佳回合混排。没有新增局外等级、装备或属性成长。

## 接入、替换美术和存档

- 新场景在 `PropDefinition` 的“战斗遭遇”字段指定配置，或调用 `BattleController.TryBegin`。战斗优先于该道具的检定 / 对话分支。`repeatable` 控制重打，`victoryFlag` 和入口的完成标记可供剧情检查。
- 背包沿用 `PropGameState`，地图物品可填写相同 inventoryKey。
- `Assets/Resources/Battle/BattlePresentation.asset` 替换背景、主角、图标、铜币、特效；敌人专属立绘替换敌人资产的 Battle Portrait。占位 PNG 在 `Assets/Battle/Art`。参考画布 1600×900，其他比例等比缩放。
- 战斗覆盖并冻结原地图；战前位置、背包、检定、剧情与地图对象另存回退快照。战中读档后仍可逃跑恢复，有会话时自动保存探索状态。
- 战斗会话 version 3 保存五亲属性快照、本轮铜币、已揭爻、开放技能、全场次数、状态、意图、敌方游标与数值版本。提交物品或胜利事务时拒绝半完成存档。外层 BattleSnapshot 与现有游戏存档版本保持兼容。
- 旧战斗会话 version 1 经 BattleLegacyEngine 继续逐技能定卦，不强行重抽或重复扣 MP；新战斗采用新流程。缺少战前快照的旧存档仍可继续，逃跑禁用。旧成绩使用 legacy 标签。
- 修改正在进行的战斗引用的技能数值或数值版本，可能使存档一致性验证失败；调参后从新游戏 / 新战斗开始验证。

## 验证与结构

`Tools > 战斗系统 > 运行战斗验证`：真实 PlayMode 核验规则、存档、界面与五个场景，输出 `Validation/battle-test-report.json` 及各页面截图。

`Tools > 战斗系统 > 运行流派与物品数值模拟`：运行 88,000 场配对种子战斗，覆盖六种首领加点、四种策略、三种物品包及普通遭遇，输出 `Validation/battle-balance-report.json`。每组 1,000 个相同种子，只使用玩家可见信息。验收要求无两回合首领胜利、纯攻击及官鬼 8 点均 0 胜、指定续航 / 控制 / 防御流派无物品胜率至少 80%、默认均衡流派带初始包胜率至少 80%，以及无超时。两项测试均使用隔离存档并恢复原场景。安装菜单只补缺失资产与占位引用，不覆盖现有配置、美术或场景。

结构：BattleEngine 负责结算；BattleController 负责时序、地图锁定与回退；BattleView 为 uGUI；BattlePresentation 管理素材；BattleProgressData 保存成绩；BattleLegacyEngine 兼容旧会话；BattleSelfTest、BattleBalanceTest 验证功能及数值。
