# 检定与六爻起卦

这版流程为：事件入口 → 铜币起卦 → 六爻排盘 → 行为加值 → 玩家选择 → 数值比较 → 成败分支 → 后续剧情。排盘与评分以用户提供的《六爻排盘.docx》脚本为依据，铜币结果、日期、角色基础值和行为加值都随会话存档。

## 试玩

1. 打开 `Assets/Scenes/ChecksDemo.unity`，点击 Play，再在主菜单选择开始游戏，将 8 点分配到五亲属性并确认。
2. 靠近观测站门控终端按 E，进入起卦界面。
3. 点击投掷按钮：三枚铜币同时抛起、翻转、落定，结果从初爻向上填入本卦和变卦。勾选“快速连续投掷”可一次点击完成剩余轮次。
4. 六次完成后，界面显示本卦、变卦和五类行为加值。点击“选择行动”，再按 E / Space 展开行动，使用 1 / 2 / 3 或按钮选择。
5. 左侧维修包可拾取，按 I 查看背包。维修行动需要并消耗一个维修包。
6. 按 E / Space 继续结果、分支及后续剧情；Esc 关闭。关闭后重新交互会保留此次铜币结果及已揭示进度。

申请通行使用兄弟属性、目标 8；维修使用子孙属性、目标 9；强行切断门锁使用妻财属性、目标 12。新游戏的基础值来自创建角色时分配的 8 点，实际结果会加入此次排盘产生的加值。失败也会继续剧情，例如强行开门失败增加 15 侵染并发现侧路。当前演示目标沿用事件配置，可在事件 Inspector 中调整。

## 输入与评分约定

- 每枚铜币正面为 3、背面为 2，每次三枚相加得到 6 / 7 / 8 / 9，连续六次，输入顺序为初爻到上爻。
- 6 为老阴，变阳；7 为少阳，不变；8 为少阴，不变；9 为老阳，变阴。
- 月令和日辰是游戏配置，例如“巳月”“戊子日”。当前没有将系统日期转换为农历，进入会话时固定事件所配置的日期。
- 评分保持文档脚本：来源五行生本爻 +1，克本爻 -1，其余 0；考虑月令、日辰、其他动爻的原五行，以及自身变出爻的五行。其他动爻排除本爻自身。
- 同类六亲多爻取最高分，全部为负分时保留负分；缺类为 0。变卦六亲沿用本卦宫五行。
- 父母、子孙、官鬼、妻财、兄弟分别映射现有五种行为。新会话中旧“我 / 认知”行为兼容映射到父母；新事件可将理解、分析归父母，将观察、探索归兄弟。旧完成会话按原冻结值恢复。排盘保留世爻得分作为文档输出，存档内部第六槽仅用于兼容。
- 本次文档评分与此前 Excel 中“同五行 +1、部分反向关系 -1”的表格不同。本实现采用文档脚本，未混用两套规则。

事件 Inspector 的“起卦与排盘”可以配置日期和固定随机种子。固定种子用于测试复现，正常游戏关闭该选项。随机数在创建会话时生成一次，动画仅揭示已固定的币面；中途关闭、重新交互、快速模式或读档都不会重新生成结果。

## 会话与结算

Preparing 表示起卦尚未完成，不能提交行动；六次揭示且排盘完成后转为 Ready。角色基础值在创建会话时冻结，随后依然以 `基础值 + 行为加值 >= 目标值` 判断成功。

选择行动立即提交，扣除配置的消耗物品并应用分支。提交前关闭不扣物品；提交后关闭保留结果和后果，不重复扣费或发奖。看完后续对白转为 Completed。不同道具实例各自拥有会话；旧版存档中没有起卦数据的会话仍按已保存的加值恢复。

## 运行日志

Unity Console 搜索“检定链”，每个会话带有自己的短 ID。记录事件入口、日期与种子、每次三枚币面、6/7/8/9 输入、本卦与变卦、世应、逐爻生克明细、五亲行为加值、最终比较、分支后果及剧情完成。旧六属性会话仍保留原有日志格式。不会按动画帧刷日志。

同时逐条追加 UTF-8 JSONL 日志：

- 编辑器：`Validation/RuntimeLogs/check-logic.jsonl`
- 发布游戏：`Application.persistentDataPath/Logs/check-logic.jsonl`

每行包含完整 sessionId、eventId、contextId，以及序号、阶段、消息和 UTC 时间。会话快照也保留逻辑链，方便将一次输入与最终输出对应起来。

## 接入与验证

- `LiuYaoPaiPan.PaiPan(月令, 日辰, 六爻数组)` 返回结构化排盘，`PaiPanToString` 可输出完整文本。
- `CoinCasting.Cast(seed)` 生成固定输入，`FromFaces` 支持直接传入十八个币面。
- `CheckPipeline` 创建起卦准备会话，仍允许显式注入旧的占位提供器，便于验证局部检定流程。
- `CheckActorState` 管理揭示、排盘、提交、一次性后果和存档一致性；`CheckCastingUI` 管理动画与界面。

**Tools → 检定系统 → 验证起卦排盘** 检查输入覆盖、独立数值样例、准备阶段、真实动画界面、日志顺序和存档恢复，输出 `Validation/divination-results.json`。**预览起卦排盘界面** 捕获界面用于检查。

原有“运行流程自检”使用显式占位输入验证通用检定分支；“运行原流程回归”验证果实交付和菜单存档。所有编辑器验证先拒绝未保存场景，结束后恢复原场景。
